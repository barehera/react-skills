## Thread 1: `src/features/tasks/components/task-bulk-archive-bar.tsx`

First version:

```tsx
const queryClient = useQueryClient()
// …
onClick={async () => {
  await archive.mutateAsync({ projectId, taskIds: selectedIds })
  await queryClient.invalidateQueries({ queryKey: ["tasks"] })
  onArchived()
}}
```

**Marco:** Cache work in a component, and a hand-written `["tasks"]` key that
also refetches every project's list and every detail. The hook should own this.

**Agent:** The selection has to clear only after the list has refetched,
otherwise the archived rows flash back for a moment. The skill's example
invalidates in `onSuccess` without returning the promise, so `mutateAsync`
resolves before the refetch. Awaiting it in the component was the only way I
saw to sequence it.

**Marco:** Return the promise from the hook's `onSuccess`: TanStack waits for
it before the mutation (and the per-call `onSuccess`) resolves. Use
`taskKeys.list(projectId)`.

Resolved. Final hook returns `queryClient.invalidateQueries({ queryKey:
taskKeys.list(projectId) })` from `onSuccess`; the component calls
`archive.mutate(vars, { onSuccess: onArchived })`.

function SelectionBar({ count, actions }: { count: number; actions: SelectionBarAction[] }) {
  return (
    <div role="toolbar" className="flex items-center gap-2 …">
      <span>{count} selected</span>

**Marco:** This is a config array. The next screen will want an icon, a

`SelectionBarAction` forever. Let the consumer render its own buttons.

**Agent:** Changed to `SelectionBar`, `SelectionBarCount`, and
`SelectionBarActions` parts; the adapter renders its own `Button` inside
`SelectionBarActions`, and the count text is a child.

Resolved.

## Thread 3: `src/features/tasks/server-state/mutations/use-archive-tasks-mutation.ts`

**Marco:** Why isn't archive optimistic like delete? The rows should disappear
immediately.

**Agent:** The server rejects any task that still has open subtasks (422), and
the client does not load subtasks for the list, so the result is not
predictable from the input. The skill says to wait for the server in that
case. I added a business-logic comment to the hook.

**Marco:** Fair, product confirmed partial rejection is expected. Keeping it
non-optimistic.

Resolved, no change.
